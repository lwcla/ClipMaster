# 共享媒体 UI 组件方案

## 当前状态

图片提取页、下载记录页和视频提取页都需要展示媒体缩略图、图片预览弹层、加载/成功/失败状态和不可读媒体占位。此前拆分主要按页面目录落文件，虽然降低了单个页面文件复杂度，但图片预览、缩略图和轻量状态提示这些跨页面能力仍散落在页面 package 中，后续容易重复实现或出现视觉分叉。

本方案作为共享媒体 UI 的主文档。后续涉及图片预览底部弹层、可选择图片缩略图、普通图片缩略图、媒体不可读占位、行内加载/成功/失败状态和居中状态容器的修改，优先更新本文；页面文档只记录本页面接入方式和差异化业务行为。

## 目标

- 把两个以上页面使用、且业务契约稳定的媒体 UI 组件放入 `ui/widget`。
- 保留页面自己的业务编排、ViewModel、导航、权限、删除授权和下载状态机。
- 共享组件只接收稳定 UI state、图片请求模型和回调，不直接依赖页面 ViewModel、Repository 或具体数据库实体。
- 图片预览组件支持本地 URI、网络图片、反盗链请求头、长图滚动、动图解码和可选底部动作。
- 轻量状态组件统一加载、成功和失败的图标、字号、颜色与点击区域。

- 不把业务卡片、Tab/Pager 外壳、删除确认弹窗和页面级工具栏强行抽成公共组件。

## 组件归属规则

- Compose 组件默认按公共组件设计。只要组件表达的是视觉结构、交互模式、布局容器、预览弹层、选择控件、状态展示或常见操作区，而不是当前页面独有状态机，就应优先放在 `ui/widget` 或合适的共享 UI 包中。
- 公共化按复用半径分层：同一 feature 多页面复用时先放 feature 级组件目录；跨 feature 或后续多个业务域可能复用时放到 `ui/widget` 或共享 UI 模块，避免所有组件无差别集中到一个目录。
- 页面目录只保留强绑定当前页面 ViewModel、导航、权限、一次性副作用、路由参数或特定业务实体且难以解耦的组件；这类组件需要能说明为什么只能用于当前页面。
- 页面可以保留薄适配层，将 `ImageExtractItemData`、`ImageCandidateData`、下载记录 item 等业务实体转换成共享组件需要的 UI state、请求模型和事件回调；共享组件本身不直接依赖页面 ViewModel、Repository 或具体数据库实体。
- 当前只有一个页面使用但形态明显通用的组件，也应优先公共化，避免后续页面复制实现；如果因风险或需求不稳定暂不公共化，需要在对应页面文档的“开放问题”或“后续待办”中记录原因和收敛方向。
- 公共组件参数优先使用具名 UI state、config、sealed state、slot 和 callback。出现大量 `isXxx`、`showXxx`、`enableXxx` 或可空参数组合时，需要重新评估状态建模，避免组件演变成万能入口。
- 公共组件默认提供 `modifier: Modifier = Modifier`；复杂内容区域优先提供 slot，例如标题、操作区、页脚和空态内容，避免为了单个页面追加一次性参数。
- 文案由语义稳定性决定位置：跨页面通用文案可以由共享组件读取字符串资源；页面语义、业务动作、错误原因、统计口径和流程提示应由调用方传入。
- 共享组件内部只保留展开、滚动、动画、焦点、临时输入等纯 UI 局部状态；导航、权限、下载启动、数据库观察、网络请求和跨页面业务副作用必须留在页面、ViewModel 或专门 state holder。
- 复杂公共组件应提供 `@Preview` 或 sample state，并覆盖正常态、空态/失败态、长文案或极端内容中的关键场景，便于后续独立验证，不依赖完整页面启动。

## 最终实现

- `ui/widget/SharedImagePreview.kt` 负责图片预览底部弹层、可选中图片缩略图、普通图片缩略图、动图 ImageLoader、图片请求构建、请求头适配和媒体不可读占位。
- 共享图片请求通过 `ImageRequestHeaderBuilder.IMAGE_REQUEST_ACCEPT` 复用 Worker 下载链路的图片 Accept，避免预览和下载内容协商规则分叉。
- `ImagePreviewComponents.kt` 保留图片提取页的实体适配层，只把 `ImageExtractItemData` 和 `ImageCandidateData` 转成共享图片请求与共享预览元信息。
- 下载记录页图片预览和历史缩略图接入共享图片预览/缩略图组件；下载记录卡片本身仍留在页面 package，因为它包含视频任务、图片批次、重试和多选语义。
- `ui/widget/MediaStateContent.kt` 负责居中状态容器和行内加载/成功/失败状态。图片提取页与视频提取页接入该组件，页面只决定文案、点击回调和后续业务动作。

## 测试验证

- 图片提取页实时网格和最终选择网格仍固定一行四张，新增候选默认选中，用户取消选择和滚动位置不因探测完成丢失。
- 图片提取页缩略图点击仍打开带元信息和保留/移除按钮的底部预览，GIF/Animated WebP 尽量正常播放。
- 下载记录页图片缩略图点击仍打开单张底部预览，高图可在弹层中纵向滚动查看完整内容。
- 下载记录页本地文件删除占位、视频首帧占位和图片批次空缩略图显示不变。
- 视频提取页加载、失败重试状态视觉保持一致，点击失败状态仍触发重试。
- 运行 `./gradlew :app:compileDebugKotlin` 验证编译。

## 已知取舍

- 当前不抽完整相册、左右切换、缩放、暂停动图或播放器组件，避免公共组件过早承担复杂业务。
- 下载记录页删除弹窗、选择操作条和历史卡片没有上移，因为它们绑定下载记录领域语义，跨页面复用价值不足。
- 图片提取页的候选 key、默认选择、副作用和滚动状态仍在页面层，避免共享缩略图组件理解探测阶段状态机。

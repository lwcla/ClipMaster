# 仓库专用 Skill 语言规则方案

## 当前状态

项目专用 skill 位于 `.codex/skills/`，用于约束当前仓库的代码修改、架构边界、Compose UI、文档日志、备份覆盖、最终自检和 Git 操作。此前这些 `SKILL.md` 与 `agents/openai.yaml` 主要使用英文描述，虽然不影响机器识别，但与仓库内“注释、文档、日志、提交信息使用简体中文”的维护习惯不一致。

## 目标

- 将当前仓库内所有项目专用 skill 的触发说明、正文流程和 UI 元数据改为简体中文。
- 保留目录名、`name`、命令、路径、类型名、配置 key 和稳定协议字段等机器识别标识，避免影响触发和工具调用。
- 固化后续规则：以后新增或更新 `.codex/skills/` 下的项目专用 skill 时，默认使用简体中文创建。

## 范围

- `.codex/skills/*/SKILL.md`
- `.codex/skills/*/agents/openai.yaml`
- `AGENTS.md`
- 本方案文档

不修改系统级 skill，不修改用户全局 skill，也不修改项目业务代码。

## 实现规则

- `name` 字段和 skill 目录名继续使用原有英文 kebab-case，确保触发标识稳定。
- `description`、标题、流程说明、阻塞条件、最终回复要求和 UI 元数据使用简体中文。
- 第三方 API 名称、命令、文件路径、类名、注解、Gradle task、Git 命令和配置 key 保留原文。
- 如果后续新增引用文档、脚本或示例，也应优先用简体中文解释目的、输入输出、边界和验证方式。

## 日志与诊断计划

本次改动仅调整本地规则文档和 skill 元数据，不引入运行时代码、后台任务、网络、文件 IO 或数据库副作用，因此不新增应用日志。诊断方式以静态检查为主：

- 使用 `rg` 检查本地 skill 中是否仍存在明显英文标题和英文工作流句子。
- 使用 skill 校验脚本检查 `SKILL.md` frontmatter 的基本合法性。
- 使用 `git diff --check` 检查空白和格式问题。

## 验证计划

- 运行 skill 校验脚本覆盖 `.codex/skills/*`。
- 运行 `git diff --check`。
- 抽查 `SKILL.md` 和 `agents/openai.yaml`，确认说明已改为简体中文。

## 已知取舍

- `name`、目录名、命令、路径、类型名和配置 key 保留英文，属于稳定机器契约，不按自然语言本地化。
- 不批量翻译系统级 skill，因为它们不属于当前仓库专用规则，且由 Codex 系统维护。

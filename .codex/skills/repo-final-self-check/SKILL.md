# 仓库最终自检

代码、文档或规则改动完成后，最终回复前立即使用本 skill。

## 回复前检查

1. 除非有明确原因，运行 `git diff --check`。
2. Kotlin/Compose/Android 改动运行最贴近的编译或测试命令；没有运行时说明原因。
3. 确认是否需要更新文档，以及是否已经更新。
4. 确认复用检查结果：
   - 复用了已有能力；或
   - 因职责、依赖方向、契约不稳定或风险原因没有复用。
5. 确认组件、类、方法变化：
   - 新增、拆分或移动了哪些组件、类、方法、mapper、formatter、validator、工具、DAO、state model；
   - 或确认没有这类变化。
6. 确认注释规则：
   - 新增或修改的每个方法、构造函数、扩展函数、Composable、回调、协程任务、Worker 入口和工具函数是否都有简体中文注释；
   - 新增或修改的每个变量声明、字段、常量、配置项、阈值、状态字段、缓存字段、集合、正则、脚本、SQL 片段和协议 key 是否都有简体中文注释；
   - 注释是否说明业务用途、输入输出、取值依据、边界条件、失败语义、生命周期或修改风险，而不是只复述语法；
   - 如果存在未补注释，是否已作为规则例外记录原因、风险和后续补齐边界。
7. 确认 `$repo-unit-test-gate` 的判断结果：
   - 是否需要新增或更新单元测试；
   - 是否已运行受影响模块的单元测试命令；
   - 如果未补测试，原因、风险和后续补测边界是否已记录。
8. 确认规则例外：
   - 临时未拆分；
   - 未补测试；
   - 未补方法或变量注释；
   - 未新增日志；
   - 未更新文档；
   - 未做 R8/release 验证；
   - 未更新备份覆盖；
   - 其他已记录例外。
9. 确认没有引入隐私或日志风险。
10. 确认没有回退或覆盖用户的无关改动。
11. 汇总本次实际触发并遵循的项目 skill；如果只是回答问题且未触发代码类 skill，最终回复也要说明。

## 最终回复格式

保持简洁，但必须包含：

- **方案文档**：更新了哪份文档，或为什么不需要；
- **复用检查**：复用了什么，或为什么不能复用；
- **组件/类/方法**：改了什么，以及拆分决策；
- **注释规则**：新增或修改的方法、变量、字段和关键分支是否已补齐简体中文注释；未补时说明原因、风险和后续补齐边界；
- **单元测试检查**：`$repo-unit-test-gate` 判断结果、是否补测试、运行了哪些测试命令；未补时说明原因和风险；
- **规则例外**：没有例外，或列出已记录例外；
- **验证结果**：命令和结果，或未运行原因。
- **使用的 skill**：列出本次实际使用的项目 skill；如果未触发代码类 skill，则明确说明。

很小的非代码文档改动可以压缩成一小段，但不能省略以上信息。

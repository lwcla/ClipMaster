# 搜索页方案

## 当前状态

已完成第一版搜索页设计、来源 App 多选筛选和搜索结果复用 `ClipResultList` 的页面差异。搜索页只搜索未进入回收站的数据，删除时复用统一删除选择弹窗。本次调整折叠搜索的时间语义：普通搜索继续按剪贴时间筛选和排序，折叠搜索按折叠时间筛选和展示；排序先显示置顶数据，再在对应分组内按折叠时间倒序。`ClipResultList` 的卡片结构、按钮布局、侧滑方向、动画阈值和通用测试验证以 `docs/clip_result_list_plan.md` 为主文档；后续搜索相关需求、筛选、高亮、搜索范围或搜索页差异行为发生变化时，必须同步更新本文档。

磁力搜索已经作为独立页面落地，详见 `docs/magnet_search_plan.md`。普通剪贴搜索页继续只负责剪贴内容检索、来源 App 筛选和剪贴搜索历史；磁力搜索不复用 `SearchViewModel`、`SearchHistoryRepository` 或 `ClipResultList`，避免剪贴内容搜索和 Academic Torrents 本地索引搜索在数据源、历史表、备份字段和点击副作用上互相污染。

本轮 UI 刷新将搜索页顶部交互收敛为稳定结构：返回标题栏、固定搜索框、紧凑筛选行和结果区。搜索框与筛选区不再跟随结果列表连续折叠，避免键盘弹出、历史覆盖和筛选高度变化时挤压结果区域。

搜索历史已完成实现：普通搜索和折叠搜索会分开保存历史，输入时模糊匹配当前范围历史并显示历史列表。当前数据库版本已包含折叠时间并处于 8，本次搜索历史按已确认计划从 8 升到 9。

搜索框已收敛为固定单行输入：顶部搜索框高度保持稳定，粘贴多行文本时会把换行折叠为空格，避免多行内容挤压下方结果列表空间。

来源 App 选择已接入共享显示名扩展：当来源记录没有应用名时，选择列表和单选后的筛选 Chip 显示“未知”，包名继续作为副标题或缺失候选兜底用于识别；完整共享规则以 `docs/source_app_display_plan.md` 为准。

来源 App 选择弹窗将“全选”从列表项提升到标题右侧，并打开时跳过半展开状态。弹窗内部允许临时取消所有来源，但此时“确定”禁用，不提交到搜索筛选；外部筛选语义继续使用空集合表示“全部来源”，集合内的空字符串包名表示“未知来源”。

当前代码组织按页面入口与局部组件拆分：`SearchPage.kt` 保留搜索范围、稳定顶部控件、结果列表和弹窗状态编排；`SearchControls.kt` 承载搜索框、筛选 Chip 和旧折叠容器兼容实现；`SearchHistoryComponents.kt` 承载历史面板、历史行、高亮与清空确认；`SourceAppPickerComponents.kt` 承载来源 App 选择弹窗和草稿选择状态，避免单个页面文件继续混合多类 UI 职责。

## 目标

- 在剪贴列表页标题栏右侧提供搜索入口，点击后进入独立搜索页面。
- 搜索页面支持按关键词、时间范围和来源 App 筛选剪贴记录；普通搜索时间范围使用剪贴时间，折叠搜索时间范围使用折叠时间。
- 普通搜索默认只搜索未折叠剪贴记录；折叠数据搜索复用同一个搜索页，通过路由范围限制为只搜索折叠数据。
- 搜索结果不包含回收站数据；回收站搜索不进入第一版，详见 `docs/recycle_bin_plan.md`。
- 搜索结果沿用列表页的卡片样式和交互，并在命中内容中高亮显示搜索关键词。

## 范围

- 调整列表页搜索入口。
- 新增搜索页路由、页面和 ViewModel。
- 扩展数据层查询能力，支持关键词、时间和来源 App 的组合筛选。
- 抽取列表页结果卡片和结果列表，供列表页和搜索页复用。
- 新增或调整用户可见文案时，按项目规则写入对应 `strings.xml`。

## 用户体验

- 列表页标题栏右侧展示搜索图标按钮，点击进入搜索页。
- 搜索页顶部提供返回入口、搜索输入框和筛选入口，输入区保持稳定高度，不随结果列表滚动折叠。
- 搜索输入框始终按单行高度展示；多行粘贴内容会在状态层规整成空格分隔的单行关键词，避免顶部区域高度变化影响结果列表可用空间。
- 时间筛选第一版提供：全部、今天、近 7 天、近 30 天。
- 来源 App 筛选提供：全部来源和已记录过的具体 App；当前调整支持同时选择多个来源 App。
- 搜索结果复用共享 `ClipResultList`，卡片结构、斜向快捷动作区、右滑菜单、复制、置顶、删除、详情跳转和通用侧滑规则以 `docs/clip_result_list_plan.md` 为准。
- 搜索结果列表底部与普通列表、折叠列表保持一致，保留 12dp 轻量留白，避免和首页底部导航或系统手势区之间出现过大空白，也避免贴得过紧。
- 搜索页只维护与搜索相关的差异：传入当前关键词用于可见文本高亮，并根据路由范围切换标题、空态和继续右滑动作；普通搜索继续右滑折叠数据，折叠搜索继续右滑取消折叠。
- 普通搜索结果和普通列表一样读取快捷动作设置；设置不是“无（整卡进入详情）”时启用左下斜向快捷动作区，快捷动作区执行复制、置顶、删除或折叠，其余区域进入详情。折叠搜索不启用快捷动作区，不显示斜向背景。
- 折叠搜索结果保留置顶/取消置顶入口，卡片时间展示为“折叠于 X”，时间筛选 Chip 也按折叠时间过滤；排序先置顶优先，再按折叠时间倒序。
- 来源 App 筛选弹窗使用多选勾选交互，点击具体 App 只切换弹窗内草稿选中状态，不立即关闭弹窗，也不立即刷新结果；标题右侧“全选”负责批量选择，点击“确定”后统一应用。
- 来源 App 筛选弹窗打开时跳过半展开状态，并使用 `LocalConfiguration.current.screenHeightDp.dp * 0.86f` 作为内容最大高度；来源很多时列表内部滚动，底部按钮保持可见。
- 来源 App 筛选弹窗的“全选”使用普通 `Checkbox + 全选`，不使用三态半选；全部选中时显示选中，部分选中或 0 个选中时显示未选中。
- 从全部来源状态取消某个具体 App 时，弹窗内部会先展开为全部已知来源集合再移除该 App；重新选回最后一个未选 App 后，草稿自动归一回全部来源。
- 点击已选中的“全选”会临时取消所有来源，底部显示“已选 0 个来源”并禁用“确定”；该 0 选中状态只存在于弹窗草稿中，不会提交到 ViewModel，外部 Chip 保持上一次已应用筛选。
- “未知”来源可能对应空包名；当用户只选择“未知”时，提交给 ViewModel 的集合必须是包含空字符串的非空集合，而不是空集合，避免被误判为“全部来源”。
- 来源 App 名称为空时，选择列表显示资源化“未知”文案，仍展示包名副标题帮助用户确认具体来源；显示名兜底规则复用 `docs/source_app_display_plan.md` 的共享方法。
- 搜索结果列表上滑时先连续收起搜索框和筛选区；列表下滑时先连续展开搜索框和筛选区，折叠区到达边界后才把剩余滚动交给列表，保证用户调整筛选条件的入口优先可见。
- 当搜索关键词非空时，在搜索结果卡片的可见文本中高亮命中的关键词。
- 当没有结果时展示搜索页专用空状态文案。

## 高亮规则

- 高亮只针对关键词搜索，不针对时间筛选或来源 App 筛选。
- 第一版高亮范围包含：
  - 剪贴内容 `content`
  - 链接预览标题 `linkTitle`
  - 来源 App 名称 `appName`
- 不高亮不可见字段，例如链接描述、站点名、包名等；这些字段可以参与搜索命中，但不应让用户看到没有上下文的高亮。
- 高亮实现建议通过 `AnnotatedString` 完成，普通列表页传空关键词，搜索页传当前搜索词。
- 搜索词需要先去除首尾空白，按空格拆分多个词，并去重，避免空关键词导致异常高亮。
- 英文、URL 和包名类内容按大小写不敏感匹配。
- 第一版优先高亮完整词；中文 FTS 模糊命中但可见文本里没有完整词时，暂不做逐字碎片高亮，避免视觉噪声。

## 数据方案

- 现有 `ClipRepository.searchAllClips(userInput)` 只支持关键词，并返回 `Flow<List<ClipShowEntity>>`；搜索页第一版建议改为分页数据流，避免历史数据较多时一次性加载。
- 在 `ClipDao` 增加搜索用 `PagingSource<Int, ClipDetail>` 查询，支持以下参数：
  - 关键词查询
  - 起始时间 `startTime`
  - 结束时间 `endTime`
  - 来源 App 包名集合 `sourceAppPackages`
- 关键词为空时，按时间和来源 App 集合条件查询全部匹配记录。
- 关键词非空时，复用现有 FTS 查询思路，并叠加时间和来源 App 集合条件。
- 来源 App 筛选状态使用空集合表达“全部来源”，非空集合表达多选包名；DAO 查询使用 `IN (:sourceAppPackages)` 匹配任一已选来源。空字符串包名是“未知来源”的合法筛选键，ViewModel 和 Repository 只做去重、排序与必要的首尾空白规整，不能把它过滤成空集合。
- 搜索结果排序沿用当前范围的时间语义：普通搜索置顶优先并按剪贴时间倒序；折叠搜索同样置顶优先，关键词命中质量之后按折叠时间倒序；所有搜索 Paging 查询都在最后追加 `id DESC`，用于同分同时间数据的唯一稳定排序，避免分页边界重复返回同一剪贴记录。
- 在 `SourceAppDao` 增加加载全部来源 App 的查询，供搜索页筛选器使用。
- Repository 层暴露搜索分页数据和来源 App 列表给 `SearchViewModel`。

## UI 复用方案

- `ClipResultList.kt` 是普通列表、搜索结果和折叠列表复用的共享结果组件，完整 UI 与交互细节集中维护在 `docs/clip_result_list_plan.md`。
- 搜索页通过共享组件参数表达页面差异：`highlightQuery` 传当前关键词；`emptyText` 随普通搜索/折叠搜索切换；`swipePastActionText` 和 `onSwipePastAction` 随 `SearchScope` 切换为折叠或取消折叠；只有普通搜索传入快捷动作设置并启用斜向快捷动作区。
- 删除、复制、置顶和点击详情继续通过回调传入，避免共享组件直接依赖搜索页 ViewModel；删除弹窗统一提供移入回收站和彻底删除。
- 搜索框和筛选区由 `SearchPage` 固定放在结果区上方，不下沉到 `ClipResultList`；共享列表只继续负责剪贴 item 和分页状态，避免普通列表、折叠列表、回收站被搜索页特有顶部控件影响。

## 搜索历史待实现计划

### 当前状态

搜索历史方案已完成。当前已按确认计划落地 Room 表、Repository、ViewModel、Compose UI、字符串资源和验证。

### 目标与范围

- 为搜索页增加持久化搜索历史，普通搜索和折叠搜索按当前 `SearchScope` 完全隔离。
- 用户输入时按当前输入模糊匹配历史；搜索框聚焦且有匹配历史时，用历史列表临时覆盖结果区。
- 用户按键盘“搜索”后保存当前非空关键词；点击历史项会填入关键词、刷新该历史时间并关闭历史列表。
- 搜索历史只保存关键词，不保存时间筛选和来源 App 筛选；点击历史项只恢复关键词，其他筛选继续沿用当前页面状态。
- 支持单条删除和清空当前搜索范围历史；普通搜索和折叠搜索的清理互不影响。

### 用户体验

- `SearchBar` 增加焦点状态、`ImeAction.Search` 和提交回调。
- 聚焦搜索框时显示当前范围历史；输入为空显示最近历史，输入非空按包含关系模糊过滤。
- 历史列表覆盖结果区；显示历史时搜索框和筛选区保持稳定高度，不触发结果列表驱动的顶部折叠。
- 历史项高亮当前输入命中的部分，便于识别匹配原因。
- 历史项点击填入搜索框并提交；单条删除不影响当前搜索结果。
- 输入后如果没有历史命中，不显示历史空面板，直接继续显示搜索结果。
- “清空”只清当前搜索范围历史，并弹确认。
- 删除或清空历史只管理历史记录，不清空搜索框、不重置时间/来源筛选、不把当前搜索刷新成空搜索。
- 系统返回键在历史列表显示时优先收起历史列表和搜索框焦点，再次返回才退出搜索页。

### 数据流与接口

- 新增 Room 搜索历史表，数据库版本从 8 升到 9。
- 搜索历史字段包含历史 id、原始关键词、规范化关键词、是否折叠范围、更新时间。
- 规范化关键词使用 `trim + lowercase(Locale.ROOT)`；同一范围内按规范化关键词去重，展示文本保留用户最后一次提交的原始写法。
- 增加唯一索引 `is_folded + normalized_query`，把普通/折叠隔离和同范围去重固定在数据库约束里。
- 增加查询索引 `is_folded + updated_at`，服务当前范围最近历史读取。
- 每个范围最多保留最近 50 条；空白或超过 200 字符的关键词不入历史。
- 新增 `SearchHistoryDao`、`SearchHistoryRepository` 及 Hilt 绑定；`SearchViewModel` 通过 `ClipVisibilityScope` 查询、保存、删除当前范围历史。
- `SearchHistoryRepository` 暴露 `observeHistories(scope, keyword)`、`saveHistory(scope, query)`、`deleteHistory(id)` 和 `clearHistories(scope)`。
- `SearchViewModel` 新增 `searchHistories`、`submitCurrentQuery()`、`selectHistory(query)`、`deleteHistory(id)` 和 `clearCurrentScopeHistory()`。
- 历史提示只查询搜索历史表，使用 `LIKE '%keyword%'` 做本地模糊匹配；剪贴内容结果仍走现有分页搜索，避免历史提示和内容搜索互相耦合。
- 历史模糊匹配必须把 `%`、`_` 和转义符本身当普通字符处理，DAO 查询使用转义后的关键词和 `ESCAPE '\'`，避免符号输入误匹配全部历史。
- 历史查询在 ViewModel 层加 150-200ms 轻量防抖，避免每个字符都刷新历史列表；剪贴结果搜索保持现有输入即更新。

## 已知取舍

- 磁力搜索不并入本文档的剪贴搜索页；两者只复用底层通用输入框、分页状态和卡片外壳等 UI 组件。原因是磁力搜索的数据源、合法源白名单、索引缓存、磁力记录和外部 App 打开副作用都不同于剪贴内容搜索。
- 第一版时间筛选先使用固定范围，不做自定义日期区间，以降低 UI 和本地化复杂度。
- 第一版中文高亮优先高亮完整词，不做逐字碎片高亮，避免结果卡片视觉过碎。
- 普通搜索结果排序沿用列表页置顶优先规则，方便用户在普通搜索页继续看到被置顶的重要内容。
- 折叠搜索保留置顶优先规则；和普通搜索不同的是，置顶组和非置顶组内部的时间排序使用折叠时间而不是剪贴时间。
- 对只包含标点或 FTS 特殊字符的关键词，最终实现会退回普通 LIKE 查询；这是为了让 URL 片段、符号输入等场景不因 FTS 语法失败而中断搜索。
- 对可构造 FTS 的关键词，最终实现也会并入 `LIKE` 子串结果；代价是关键词搜索会比纯 FTS 多一次主表扫描，但能保证中文连续子串的命中率。
- 普通搜索不增加“包含折叠数据”开关，折叠数据只能从折叠数据入口进入搜索，保持可见范围边界清晰。

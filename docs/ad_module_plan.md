并行启动与展示约定：

- 当前候选的展示条件为“广告素材已加载成功、列表当前已有进入展示状态的真实记录、页面及广告自身允许展示、该广告位未被用户关闭”同时成立，内容条件持续生效。列表首屏不等待广告；广告也不等待全部分页、图片预览完成、滚动动作或额外固定延时。首批记录进入显示状态且素材已就绪时，广告可随该次页面更新呈现，不引入依赖每个 item 测量完成的回调链。曾经有记录不等于当前仍有内容，素材 Loaded 也不等于广告已经展示。
- 广告宿主放在页面固定区域，并始终独立于列表的加载/内容/空态分支建立。列表查询向列表提交数据，页面只向广告呈现层传递低敏内容状态，不传递实体或正文；不能把整个广告 Composable 包在 `itemCount > 0`、首批完成或空态分支内，否则请求仍会间接等待数据。
- 请求门和呈现门分开。现有 `AdSlotRequest.canRequest` 控制启动，`canReveal`/`canRevealNow` 控制首次创建广告 View，`AdmobSlotSession` 已分别保存加载后的素材与展示 View，可复用“先加载素材，条件允许再展示”。但 `canReveal = false` 不会隐藏已有 View，且该条件混合了滚动/按压安全保护，不能直接作为已有广告的持续显示开关；需增加独立内容呈现契约。列表未返回或为空不应写入 `PageAdSlot.eligible`、会话 enabled 或 suppressed：前两者会阻止申请或释放资源，suppressed 会阻止新请求及交互，却不会隐藏已有 View。真正的隐私和敏感上下文仍保持硬门禁，不能借并行启动绕过。
- 广告先完成时保留有效素材，列表首批真实记录进入显示状态之前暂不挂载 View；内容出现后直接使用同一份素材，不再发一次请求。数据库先完成时先显示记录，广告之后按自身结果显示或收起，不阻塞列表首屏。
- 是否为空沿用当前页面已经收集的 Paging 结果和首批完成状态。未返回时的 `itemCount == 0` 不能直接判为空；有旧记录的刷新也不等于无内容。不为广告新增 COUNT/EXISTS 或全量读取，已存在的折叠/回收站/下载历史数量 Flow 继续承担原业务职责；全库非空不能代替当前搜索筛选结果非空。
- 首次展示前确认空时列表显示空态，广告不呈现；已加载素材可在同一页面会话的现有生命周期和有效期内保留，后续增加记录并进入显示状态时复用。空态不产生自动刷新、循环重试或新的广告请求。该规则替代此前“初始纯空屏幕也无条件首次展示”的候选要求，并保持广告独立开始加载。
- 已经展示后，用户手动删除最后一条记录或清空列表，列表实际切到空态的同次 UI 更新关闭广告呈现，移除广告 View、关闭按钮及附属间距，禁止点击，并将广告位标记为当前不可见；不等待滚动/按压安全门才撤下广告。自动隐藏不写入用户关闭记录，不释放仍有效的素材或重建会话；后续重新出现真实记录时，可以通过既有布局安全门复用有效素材。页面退出、隐私撤销、来源不可用、素材过期和真正敏感上下文仍遵守原有释放边界；空态不产生自动刷新或循环重试。

同步隐藏的实现契约：

1. 复用页面当前收集的 Paging 快照和实际列表展示分支，形成具名的低敏内容状态，例如待返回、有真实展示内容、无内容；列表空态与广告持续呈现门必须来自同一状态。`ClipResultList` 已用 refresh 与 itemCount 区分加载/空态，并从 `itemSnapshotList` 生成真实渲染条目；下载历史也已有对应分支。后续如抽纯派生策略，放在共享分页/列表 UI 职责位置，页面只做接入，不让广告模块读取数据库或业务实体。实际渲染条目而非 placeholder、全库数量或历史有内容标记决定内容资格；下载历史视频当前刷新时优先显示加载块，不能仅凭快照中仍有记录就认定正在展示列表。
2. 删除流程仍为用户确认、现有 ViewModel/Repository/DAO 写入、Room/Paging 更新、页面重组。这里的“同步”是空态与广告收起使用同次状态更新，不是点击删除按钮就提前隐藏；取消确认、删除失败或仍有剩余记录不触发空态隐藏。不逐个删除入口发广告命令，也不另起 `LaunchedEffect` 将空态再复制为可见标记，避免两条 UI 状态不同步。当前实际没有内容时统一关闭呈现门，因此自动删除、筛选变空及短暂无内容画面也不会保留孤立广告；刷新期间实际仍显示旧内容则保持原广告。
3. 在 `PageAdSlot` 与 ad-api 的请求契约中传递持续内容呈现状态，默认按页面自身是否已有实质内容接入；它只影响实际 View 挂载、首次揭示、可见性回报和点击许可，不改变 `canRequest`、租约身份或资源所有者。独立广告宿主在加载与空态期间仍存在，普通临时遮挡/ON_PAUSE/滚动保护不被误当成内容消失。非列表页面不按剪贴数量决定广告资格；所有广告位的用户关闭规则保持一致。
4. `AdmobAdSourceEntry.NativeAdSlot` 使用 `AdPresentationPolicy` 同时判断已创建 View、当前内容许可和首次/重新挂载安全门，空态那次组合使 View 退出窗口，不能只设透明度或保留等高空壳。`AdmobSlotSession` 在自动隐藏时撤销已呈现状态、解绑 View 并保留有效资源；恢复重新通过布局安全门。其他来源共用相同纯呈现谓词。素材与脱离窗口的 View 仍由原资源/释放边界持有，退出/撤销/过期时销毁，不另建永久缓存。
5. 异步 Loaded/旧绑定回调必须读取最新内容资格及绑定身份。清空与广告加载完成同时发生时，允许保存仍有效的素材，但不能创建或挂回没有内容的广告 View；旧回调不能将当前隐藏状态改回可见。点击右上角关闭则走单位置终态和资源释放，不与自动隐藏共用关闭标记；查询 key、内容恢复及普通重组不能解除该终态。

#### A 方案进一步紧凑化（2026-09-27，候选比较记录）

目标：合并原版独立的标记行和按钮底栏，以结构调整降低高度，不靠缩小字体或隐藏必需素材压缩。高度均为普通字体、常见手机宽度下的目标区间，不是固定裁切值；长标题、较长 CTA、小屏、大字体允许增高。示意素材不代表真实广告内容或已完成的设备验收。

- A3 单行紧凑条：非视频素材约 80–96dp。左侧约 40dp 图标、中间标题及广告标记、右侧 CTA，AdChoices 独立预留角落空间；省略可选主图与正文。占位最小，但正文解释与素材展示更少，长标题/CTA 更容易触发增高。

### 暂停保留与真实离开释放（2026-09-27，已完成）

确定采用：ON_PAUSE 不主动销毁、清空驻留账本或创建新请求身份；短暂暂停后 ON_RESUME 复用仍有效的原素材。已经开始的请求可完成并暂存，但新增请求及新素材展开仍需页面实际可用、无阻塞、满足隐私资格；真正离开/停止后取消等待、销毁资源，迟到结果只销毁。ON_STOP 和 ON_DESTROY 可连续到达，释放必须幂等。撤回隐私后必须重新取得许可才能请求，不能仅因恢复 RESUMED 就加载。

### 页面返回重新加载（2026-09-27，已完成）

原因：真机首页在 4 秒时超时释放，约 6 秒才收到成功回调；已显示的广告在切后台时释放，原会话的 `acquired/attempted` 却继续阻止恢复。用户确认 AdMob 总请求预算改为 15 秒，并要求所有页面返回后重新加载。

历史实现（已由本轮暂停保留方案替代）：共享 `rememberPageAdSession` 使用独立 `PageAdSessionOwner` 管理每次可见访问，直接监听导航 Lifecycle 的 RESUMED 边界及页面明确传入的 `visibleToUser`，避免后台帧暂停时状态流合并掉离开/返回边界。离开时立即停用并清空旧会话驻留，返回时创建独立 `PageAdSession`（新 nonce、新请求账本）；旧槽的释放或迟到回调只能操作旧对象，不影响新请求。AdMob adapter 同步监听 ON_PAUSE/ON_DESTROY 关闭 SDK 会话，不依赖后台组合帧来取消加载和销毁素材。业务 `enabled`、敏感内容、隐私、弹窗和多选仍是资格限制，不能单靠资格恢复刷新会话。普通重组、分页追加或同页失败不自动循环请求。

首页 Tab 可见性与下载记录稳定选中页通过 `visibleToUser` 接入；下载记录横向拖动只阻止布局揭示，不冒充页面离开，也不销毁现有广告。其他 16 个广告位置继续使用同一个共享入口，覆盖详情、搜索、折叠、回收站、提取、下载阶段及备份流程。现有安全开关、敏感内容规则及保险丝仍优先，返回不绕过这些限制。所有后台请求仍随离开立即取消，不等待 15 秒结束。15 秒调整仅针对当前 AdMob adapter，国内来源保留各自请求超时。

## 目标

- 广告能力独立成可替换模块，宿主只依赖 `:feature:ad-api`，不直接依赖 AdMob、穿山甲、优量汇等 SDK。
- 详情页只展示一个原生广告位，位于正文卡片和链接/磁力操作区之间。
- 无广告源、广告关闭、隐私未同意、无填充、加载失败或保险丝禁用时，广告位直接隐藏且不占空白。
- 同一 APK 内已编译进来的广告源可运行时切换；新增全新 SDK 仍通过 adapter 模块和重新打包发布完成，不动态下载代码。
- 广告请求和日志禁止携带剪贴正文、完整 URL、搜索词、本地文件路径、设备标识、广告素材或 SDK 原始响应。

## 架构与模块

- `:feature:ad-api`：定义 `AdPlacement`、`AdSourceEntry`、`AdSlotRequest`、`AdSlotEvent`、`AdSourceSelector`、`AdRuntimePolicy` 和 `AdSessionFailureFuse`，并通过 Hilt `@Multibinds` 提供空广告源集合。
- `:feature:ad-debug`：通过 Hilt `@IntoSet` 注入 `debug` 广告源，只在 debug 请求下显示固定占位 UI，不接入真实 SDK。

## 详情页广告控制

- 详情页不做用户可感知频控：每次用户主动进入详情页时允许展示一个原生广告位。
- 当前共享宿主中，同一个 `clipId` 在每次详情页可见访问内最多创建一次 `requestNonce`；Compose 重组或同页状态刷新不重复创建请求，前后台切换后返回创建新访问，详见上方页面返回重新加载约定。
- `NoFill`、`LoadFailed`、广告源不可用或隐私未同意时不在当前详情页内重试。
- 详情页离开可见状态时，adapter 必须释放广告 View、loader、监听器和 SDK 回调；返回详情页可重新请求。
- 用户撤回广告隐私同意或关闭广告能力后，当前广告 View 和 loader 立即释放；已初始化 SDK 若无法反初始化，v1 只承诺停止新请求并释放当前资源。
- 详情页禁止插屏、弹窗、自动跳转、覆盖正文和抢焦点广告。
- 列表页、搜索页、下载页等连续消费场景后续必须单独规划密度、间隔和分页级频控，不复用详情页的一页一广告规则。
- 当前会话内某个广告源初始化失败或渲染失败后，`AdSessionFailureFuse` 会临时禁用该 source，并回退到其它 source 或隐藏广告位。

## 合规与 Adapter 验收

- 真实 SDK adapter 必须等待隐私同意完成后再懒初始化；用户不同意非必要个人信息处理时，核心功能仍可用，广告隐藏或降级。
- 广告 SDK 不得放在 `Application.onCreate()` 初始化；只在“隐私同意完成 + 广告总开关开启 + 首个广告位需要展示”时启动，并限制初始化耗时。
- 每接一个真实广告 SDK，必须补齐 adapter 验收清单：SDK 名称/版本、广告平台、收集信息、权限、是否读取广告 ID、初始化时机、隐私政策链接、SDK 清单条目、测试广告位 ID、正式广告位 ID、R8/consumer rules、崩溃回退策略和 release 验证命令。
- 国内广告单元 ID 继续按 debug/release 环境隔离；AdMob 按 2026-09-27 用户确认使用同一套真实 ID，开发验证通过后台测试设备模式接收测试广告，具体配置以上方真实 ID 接入小节为准。
- Google/海外 adapter 必须检查 merged manifest 是否引入 `com.google.android.gms.permission.AD_ID`，并同步 Play Data safety、广告 ID 声明和测试广告位配置。
- AdMob adapter 必须单独标注 EEA、UK、瑞士场景的 EU consent policy、UMP/CMP/TCF 要求；不能把普通隐私弹窗当作 AdMob 合规完成条件。
- 国内广告 adapter 必须补齐隐私政策、SDK 清单、权限说明、个人信息处理目的、初始化前同意策略和不同意后的降级行为。
- SDK 版本升级按高风险变更处理：每次升级都重新跑 adapter 清单、merged manifest 检查、R8 验证、Data safety/SDK 清单核对和初始化行为验证。

## 设置与备份边界

- `AdSettingsRepository` 保存 `auto`、`off` 或稳定 sourceId，只影响本机广告选择，不进入 WebDAV/本地备份。
- `AdSettingsRepository` 保存广告总开关，只影响本机广告展示，不进入 WebDAV/本地备份。
- `AdSettingsRepository.setConsent` 原子保存同意状态和政策版本；未就绪时按未同意处理，不进入 WebDAV/本地备份，也不触发 backup dirty。
- `AdSessionFailureFuse` 只保存当前进程内的临时禁用集合，不持久化、不进入备份、不触发 dirty。
- `local.properties` 中的 `uniad...`、`csj...` 和 release 签名配置属于本机/CI 构建态，不进入 WebDAV/本地备份，也不能写入运行时日志。
- 卸载重装后广告选择恢复默认 `auto`、广告总开关恢复默认开启，实际是否显示仍由广告源集合、隐私同意和渠道包决定。

## 已知取舍

- 默认构建的所有可选实现开关均为 `false`，不接真实广告 SDK；debug/internal 和 release 分别通过显式 feature 开关决定是否编译对应 adapter，广告参数只负责配置与完整性校验。该方式多一个明确开关，但与 `enableMagnetFeature` 的位置和语义一致，也避免本机残留密钥意外改变 APK 组成。
- 第一版不做远程配置后台；只保留本地 `auto`、`off`、总开关、会话保险丝和远程 kill switch 预留字段。
- 第一版不在“我的”页暴露广告源选择 UI；后续若要给内部构建开放切换入口，需要先补设置页方案和隐私文案。
- `AdConsentState.NotRequired` 只用于调试广告源和无真实 SDK 的第一版；真实广告源必须接入明确同意状态。
- 穿山甲 v1 不接开屏、插屏、激励视频、弹窗、下载类广告、列表页广告、搜索页广告、远程配置后台、统计后台或完整内部诊断面板。
- uni-ad v1 不接运营后台、收益统计后台、普通用户广告开关 UI、列表页/搜索页广告、下载类广告、插屏、开屏、激励视频、Draw 信息流或更多渠道；先用章鱼 + 泛连验证详情页一个广告位。

## 开放问题

- 优量汇、快手、AdMob 等第二广告源的具体接入顺序、渠道裁剪规则和广告单元 ID 管理策略待后续单独确认。
- 穿山甲正式上线前需要补齐第三方 SDK 目录、隐私政策更新、权限用途说明、个人信息收集清单、广告 ID/设备信息声明、审核截图/录屏留档和渠道构建报告。
- uni-ad 正式上线前需要完成 DCloud uni-ad 后台实名认证、财务审核、应用创建、包名/签名绑定、DCloud AppId、联盟 ID、详情页信息流 adpid、隐私政策 URL、第三方 SDK 清单、章鱼/泛连渠道审核材料、审核截图/录屏和渠道后台广告位截图留档。
- 当前 `ads-sdk-pro` AAR 含 `arm64-v8a` 和 `armeabi-v7a` 多个 `.so`，并在 R8 中产生大量 SDK jar 的 stack map table warning；合入前可接受为第三方 SDK 风险记录，正式上线前仍需在目标渠道 release 包上二次验证启动、加载、崩溃率和包体。
- 内部诊断面板、远程 kill switch 下发、聚合收益统计、本地事件缓存和敏感内容识别增强放到 v1.1 或后续单独方案。
- 列表页、搜索页、下载页广告位需要独立方案，重点补密度/间隔/分页级频控和连续消费场景体验。
- 是否需要灰度平台、SDK 版本快速回滚面板和广告包构建报告自动化，后续结合发布渠道与运营能力再评估。

# 回收站功能方案

## 当前状态

剪贴数据已从“删除即从数据库移除”调整为“可选择移入回收站或彻底删除”。回收站是剪贴数据的软删除范围，只保存 `clips` 表中的删除时间，不复制内容，也不清理来源 App 和链接预览缓存。

本文是回收站能力主方案文档。后续涉及回收站入口、软删除/硬删除、回收站分页、保留天数、自动清理、删除弹窗、回收站 item 交互或相关数据层查询时，必须优先更新本文；列表页、搜索页、折叠页和共享列表文档只记录接入差异。

## 目标

- “我的”页新增回收站入口，并显示 `deleted_at > 0` 的剪贴数据数量。
- 其他剪贴页面删除时提供“移入回收站”和“彻底删除”两个动作。
- 回收站页分页展示已删除数据，按删除时间倒序排列，并显示“删除于 X”。
- 回收站支持还原、单条右滑彻底删除、长按多选彻底删除、清空全部、保留天数设置和过期自动清理。
- 普通列表、搜索、折叠列表、详情和剪贴采集去重都不读取回收站数据。

## 数据与接口

- `ClipData.deletedAt` 持久化删除时间，单位毫秒；`0` 表示正常数据，大于 `0` 表示在回收站。
- 数据库版本升到 7，迁移 6 -> 7 增加 `deleted_at INTEGER NOT NULL DEFAULT 0`，并创建 `deleted_at` 单列索引和 `deleted_at + is_folded` 组合索引。
- 普通/折叠分页、搜索、详情、折叠数量、最新记录和重复内容查询全部添加 `deleted_at = 0` 过滤。
- 回收站记录不参与去重；删除后重新复制同样内容会创建新的正常记录。
- Repository 明确拆分软删和硬删接口：`moveClipToRecycleBin`、`deleteClipPermanently`、`restoreClipFromRecycleBin`、`loadRecycleBinClips`、`observeRecycleBinCount`、`clearRecycleBinPermanently` 和 `cleanupExpiredRecycleBinClips`。
- 批量软删/硬删使用事务并分块处理 id；同一批移入回收站使用同一个 `deleted_at = now`，保证回收站排序稳定。
- 清空回收站和过期清理使用条件 SQL，不先读取全部 id；批量操作对已不存在 id 保持幂等。
- 彻底删除只删除 `clips` 行，暂不清理 `SourceApp` 和 `LinkPreview` 孤儿缓存，避免误删仍被其他剪贴复用的缓存。

## 用户体验

- “我的”页入口顺序为下载记录、折叠数据、回收站、权限说明；回收站入口显示“回收站内有 X 条剪贴数据”。
- 其他剪贴页面的删除确认弹窗统一使用 `ClipDeleteChoiceDialog`，“移入回收站”为主动作，“彻底删除”为危险动作，并提示彻底删除后不可恢复。
- 回收站页标题为“回收站”，右上角显示清空和设置按钮；清空需要二次确认，确认后彻底删除回收站全部数据。
- 回收站空态显示“回收站是空的”。
- 回收站列表复用 `ClipResultList` 卡片，但隐藏复制、置顶和普通删除按钮；点击 item 只弹出还原确认，不跳详情页。
- 回收站 item 右滑到底直接彻底删除；长按进入多选，多选删除需要二次确认。
- 多选态拆分为独立的多选模式和选中 id 集合；反选最后一条数据只会让选中数量变为 0，不自动退出多选，必须由用户点击返回或完成删除后退出。
- 分页刷新、还原或后台清理导致 item 消失时，UI 清掉失效选择但保留多选模式；确认删除时自动忽略不存在的 id。
- 设置底部弹窗提供 7 天、30 天和自定义天数，显示“当前保留：X 天”；自定义范围为 1 到 3650 天。
- 保存保留天数后立即按滚动时间窗口清理过期数据，例如 7 天表示 `deleted_at < 当前时间 - 7 * 24h`。
- 删除、还原、彻底删除、清空和页面内设置清理后给轻量 Toast 反馈；后台 Worker 静默清理，不发通知、不弹 Toast。

## 生命周期和清理

- 回收站列表使用 `Pager + PagingSource` 分页加载，并由页面在 `STARTED` 生命周期内收集。
- `MineVm` 只通过 COUNT Flow 展示回收站数量，不为了统计加载回收站分页。
- `AppSetting.recycleBinRetentionDays` 保存保留天数，默认 30 天。
- 主进程启动时调度每日 `RecycleBinCleanupWorker`，并立即执行一次过期清理。
- 保存设置后由回收站 ViewModel 立即执行一次清理并反馈结果；后台 Worker 只负责删除过期数据。

## 已知取舍

- 第一版不做撤销、回收站搜索和批量还原；后续如需要应单独设计。
- 还原只清零 `deleted_at`，不更新时间戳，保留原折叠状态、置顶状态、内容、来源和时间。
- 当前没有清空入口的页面不强行新增清空；后续新增时复用本方案的双动作确认弹窗。
- 硬删除暂不做来源 App 和链接预览孤儿缓存清理；后续如需存储瘦身，单独设计缓存清理方案。

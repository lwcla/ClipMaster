### 展示与字段契约

- 继续复用 `AnnotatedString` 和现有文本截断：正文最多三行、链接标题最多两行、独立链接一行。加粗可能改变换行与高度，应沿用列表实测高度，验证侧滑和离场动画，不写死旧高度。
- 搜索页传入具名高亮配置 `ClipSearchHighlight`，包含关键词与可高亮字段；共享列表及卡片只消费 UI 配置，不依赖页面 `SearchFilterState`、ViewModel 或 Repository。普通列表/折叠列表默认不传配置，不加高亮。
- “全部字段”保留当前可见正文、链接地址、链接标题、来源名称的高亮；“剪贴内容”仅标记正文；“链接标题”仅标记真实标题；“来源 App 名称”仅标记真实来源名称。未选字段即使碰巧包含同一关键词也不标红。提取链接在内容模式下不单独扩大搜索/高亮范围，正文中的 URL 仍可正常命中。
- 不用“未知”、域名、包名或 URL 等展示兜底代替缺失标题/来源名称参与定向高亮。描述、站点名、包名等不可见字段在兼容的“全部字段”查询中仍可能命中，因此该模式暂不保证每条结果都有可见红字；本轮不扩展为命中摘要/自动滚动定位。

### 共享基础色与分层强度

以下不透明度已由用户确认并落实；快捷区和角标保留原值，实际观感仍待设备验收。

| 绘制区域 | 无有效来源主色 | 有有效来源主色 |
| --- | --- | --- |
| 卡片边框、侧滑菜单分隔线 | `outline`，100% | 来源主色，30%，保留现值 |
| 快捷操作区静态三角底色 | `outline`，5% | 来源主色，5%，保留现值 |
| 快捷操作区按压叠层 | `outline`，10% | 来源主色，10%，保留现值 |
| 置顶角标 | `outline`，40% | 来源主色，40%，保留现值 |

- 快捷区当前先绘制 5% 常驻底色，按压时再叠加 10% 同色层，两层等效不透明度为 14.5%，不是按压时把整体替换为 10%。沿用此层次避免整块区域使用不透明描边色压住正文。
- 仅替换基础色不能保证暗色快捷区足够明显：固定 `surface = #171C24` 上，5% `outline` 合成约为 `#191E27`，仍然很淡。本轮按用户要求保留 5% 底色和 10% 按压层；验收分别检查区域识别、按压反馈和正文可读性，后续是否提高强度由实际反馈决定。
- 详情按压继续使用 `onSurface` 的 3.5%，多选覆盖继续使用 `primary` 的 12%，保持各自的状态语义。颜色派生复用既有 `appColor` 和绘制路径，无需新增卡片组件或变更命中区域。
- 日志与诊断计划：这组调整属于纯 UI 配色，不增加运行时日志、持久化数据或备份契约。单元测试门禁：局部样式调整不新增单测或采用 TDD，运行 app Kotlin 编译及差异复核；无外部协议、反射或数据契约变化，不运行 R8。后续若抽出独立颜色规则须先补回归测试。

## 目标

- 为普通列表、普通搜索、折叠列表、折叠搜索和回收站列表提供同一套剪贴结果展示体验。
- 保持剪贴记录操作清晰可点：普通列表和普通搜索可按用户设置启用左下斜向快捷动作区，快捷区执行复制/置顶/删除/折叠，其余区域进入详情；置顶、删除和复制也可通过右滑菜单露出。

- 保持分页加载、空态、append 重试和切回列表后的滚动位置稳定。
- 将卡片结构、侧滑、动画、测量和滚动修正集中在组件内维护，避免页面文档和页面实现重复分叉。

## 用户体验

- 结果使用单列竖向 item，不再使用瀑布流。
- item 保留卡片、边框和来源色；展示链接、链接标题、预览图、剪贴字符串、来源 App 和时间；来源 App 名称为空时通过共享显示名工具显示“未知”。
- 剪贴字符串最多展示三行，超出省略。
- 普通列表和普通搜索在用户快捷动作不是“无（整卡进入详情）”时启用左下斜向快捷动作区：以 item 左上角到底边中点连线作为边界，边界左下侧执行用户选择的动作，其余区域进入详情；整个 item 任意位置长按都触发现有长按回调，由页面决定是否启用长按动作。
- 详情或快捷动作点击必须是稳定轻点：按下到抬起的最终位移不超过系统 `touchSlop` 才会分发点击；轻微手抖仍按系统点击容忍处理，超过阈值的列表滑动、斜向拖动和关闭状态左滑只取消 item 点击，不跳转详情。
- 启用快捷动作且动作可执行时，快捷动作区在内容下方绘制与卡片边框同源的极浅三角背景（当前代码为 `appColor.copy(alpha = 0.05f)`），帮助用户识别区域但尽量不影响阅读；按压时另叠加同色 10% 反馈层。不画硬斜线，不显示背景中的复制图标。内容仍按整张 item 宽度铺满显示，不被快捷动作区挤压或改写测量。
- 快捷动作区、按压反馈和点击命中都基于同一套三角规则：`x < width / 2f && y > (height / (width / 2f)) * x`；斜线边界默认归详情区，降低删除/折叠等高影响动作误触风险。
- 用户选择“无（整卡进入详情）”、折叠列表、折叠搜索和回收站列表都不启用快捷动作区，不显示三角背景，整个 item 点击和长按保持页面传入的现有行为。
- item 向右拖动露出左侧可用操作按钮，普通范围和折叠范围通常包含复制、置顶/取消置顶和删除；回收站可关闭普通菜单按钮。向左拖动收回；列表内只允许一个 item 菜单保持展开，新 item 开始右滑时会自动收回上一个已展开菜单。
- item 在第一段右滑菜单基础上继续右滑时显示页面传入的提示文案，例如“继续右滑折叠数据”或“继续右滑取消折叠”。
- 继续右滑超过阈值并松手后，item 先完整滑出当前卡片区域，动画结束后再回调页面更新数据库，避免 Paging 刷新导致记录半途消失。
- 右滑菜单按钮顺序为复制、置顶/取消置顶、删除；按钮宽度统一为 48dp，图标尺寸统一为 24dp，并在各自点击区域内水平和竖向居中。
- 右滑菜单删除按钮引用 `:base:general` 的 `base_general_ic_delete`，与详情页标题栏、搜索历史、下载记录多选条和回收站多选彻底删除入口共享同一删除图形；该统一范围不包含搜索历史清空、下载记录清空当前分类和清空回收站等清空类入口。
- 菜单按钮之间使用 0.5dp 固定高度分割线；分割线高度为按钮图标高度加 10dp，竖向居中，颜色与卡片边框一致。
- 置顶状态角标是卡片级视觉装饰，不响应点击；它位于卡片右上角，当前代码以 40% 不透明度（`alpha = 0.4f`）展示，只做状态暗示，避免覆盖右上角剪贴文案时影响阅读。

## 数据和参数契约

- `pagedClips` 由页面传入，组件只消费 `LazyPagingItems<ClipShowEntity>`，不直接访问 Repository 或 ViewModel。
- `listState` 由页面持有，组件负责在取消置顶排序刷新后基于该状态恢复视口。
- 当前展开菜单 id 由 `ClipResultList` 父层维护，`ClipCard` 只上报自己开始展开或收回，避免多个 item 各自保存展开态后同时露出菜单。
- `emptyText` 由页面传入，用于区分普通列表、普通搜索、折叠列表、折叠搜索和回收站空态。
- `highlightQuery` 默认为空；搜索页传入当前关键词后，组件只在可见文本中高亮命中内容。
- `swipePastActionText` 为空时只允许普通菜单阶段；非空时开启第二段继续右滑提示和动作。
- `onSwipePastAction` 只表达第二段动作回调，具体是折叠还是取消折叠由页面决定。
- 删除、复制、置顶、详情点击、还原点击和多选点击继续通过回调传入，避免共享组件直接依赖某个页面 ViewModel。
- `selectionMode` 为 true 时，组件将 item 点击语义切换为选中/取消选中，并通过 `selectedIds` 展示覆盖层；`onToggleSelection` 只负责向页面抛出选择事件，不在组件内维护选中集合。
- `ClipCard` 的 `pointerInput` 手势协程通过 `rememberUpdatedState` 读取最新 item 快照和页面回调，只解决手势协程捕获旧闭包的问题；页面级动画期间的点击命中和旧目的地保留不在共享组件内处理。
- 时间展示由页面传入展示模式；普通范围显示原剪贴时间，折叠范围显示折叠时间，回收站范围显示删除时间。
- 快捷动作由页面读取 `ClipSettingsRepository.quickAction` 后传入；加载失败前不启用依赖该设置的快捷动作。共享组件只负责按参数识别斜向区域和回调，不直接访问设置仓库。普通范围支持复制、置顶、删除、折叠和无；折叠范围与回收站不启用快捷动作区。
- 来源 App 名称展示调用 `String?.toSourceAppDisplayName()`，组件只传入拍平后的来源名称，由共享扩展读取资源化“未知”兜底；完整空名称兜底规则以 `docs/source_app_display_plan.md` 为准。

## 交互规则

- 复制：右滑菜单第一项调用 `onCopy(clip)`；普通范围快捷动作设置为“复制”时，点击左下斜向快捷动作区也调用 `onCopy(clip)`。
- 删除：右滑后点击删除按钮调用 `onDelete(clip)`，是否弹窗确认以及移入回收站/彻底删除由页面处理。
- 置顶/取消置顶：右滑后点击置顶按钮调用 `onPinToggle(clip)`；取消置顶前组件会记录当前视口，等待 Paging 排序刷新后恢复。
- 详情：未启用快捷动作区时，点击整个 item 调用 `onClick(clip)`；启用快捷动作区时，点击斜向快捷动作区之外的区域调用 `onClick(clip)`。
- 长按：长按 item 任意位置调用 `onLongClick(clip)`，当前是否有可见反馈由页面决定。
- 快捷动作：普通列表和普通搜索支持复制、置顶/取消置顶、删除、折叠和无；“删除”只打开现有删除选择弹窗，不静默删除；“折叠”只在普通范围生效，不在折叠范围反向取消折叠；“无（整卡进入详情）”完全关闭快捷动作区且不影响右滑菜单。
- 点击和侧滑统一在同一个手势入口协调：横向超过 touch slop 且符合右滑/菜单收回时进入侧滑流程；任意方向总位移超过 touch slop 但不属于 item 侧滑时取消点击，交给列表滚动或首页 Pager；即使快速滑动后首个可见事件已经是抬手事件，也要按最终位移兜底取消点击；未超过 touch slop 并正常抬手时再按斜向公式分发快捷动作或详情；到达长按时间且未超过 touch slop 时触发长按并取消点击。
- 按压态只反馈实际命中的区域：点快捷动作区时只反馈三角区，点详情区时不让左下角误亮；右滑、纵向滚动、长按触发、手势 cancel 和 item 复用到新 `clip.id` 时都必须清理按压态。
- 第二段动作：右滑露出菜单后继续右滑，或在无菜单模式下直接右滑，超过阈值并松手后播放离场动画，再调用 `onSwipePastAction(clip)`。
- 多选：页面可传入选中 id 集合，组件只展示选中态并把点击/长按回调交回页面。
- 多选态下，item 语义从“查看详情”切换为“选中/取消选中”，并暴露当前是否已选中；轻点只调用 `onToggleSelection`，不进入详情。
- 多选态下，斜向快捷动作区、右滑菜单、第二段继续右滑和右滑手势消费全部关闭；如果进入多选前已有菜单展开，组件会先把该 item 偏移收回到 0 并释放菜单归属。
- 侧滑：
  - 只允许向右展开、向左收回。
  - 新 item 开始右滑时会登记为当前展开菜单，原已展开 item 监听到菜单归属变化后自动收回。
  - 关闭状态下的左滑不消费事件，交给外层首页 Pager 切到“我的”。
  - 菜单已展开或动画中时，左滑优先由 item 消费用于收回菜单，避免展开状态直接切页。
  - 普通菜单阶段最大偏移等于左侧操作区宽度。
  - 存在第二段动作时最多可拖到完整 item 宽度，触发阈值为 item 宽度 85%；无菜单的回收站 item 也沿用该阈值。
  - 松手时按操作区一半宽度吸附；未达到第二段触发阈值时使用较长吸附动画回到菜单或收起状态。
  - 侧滑偏移按 `clip.id` 使用 `rememberSaveable` 保存，父层额外保存当前展开菜单 id，避免 LazyColumn 复用导致状态串到其他记录，同时保证最多只有一个菜单可见。

## 高亮规则

- 高亮只处理用户看得见的字段，匹配词由搜索页通过 `highlightQuery` 传入。
- 当前高亮范围包含剪贴内容 `content`、链接预览标题 `linkTitle` 和来源 App 名称 `appName`。
- 关键词会先去除首尾空白，按空白拆词、去重并做大小写不敏感匹配。
- 多个词重叠时只给尚未覆盖的位置加样式，避免重复添加 Span 造成边界不可预测。
- 普通列表和折叠列表传空关键词，不额外分配高亮片段。

## 高度和测量

- 卡片内容高度由完整宽度内容层真实测量结果决定。
- 不再使用 `IntrinsicSize.Min + fillMaxHeight` 让按钮反向参与高度测量，避免置顶重排后小 item 继承旧首条大 item 高度。
- `ClipCard` 不再为复制入口或快捷动作区扣除宽度；三角背景和统一手势入口都使用卡片最终高度跟随内容，不参与内容测量。
- 复制入口只存在于右滑菜单和可选快捷动作中，不再使用背景图标；菜单分割线仍按固定高度竖向居中，不拉满卡片高度。
- 左侧侧滑操作区通过外层 `matchParentSize()` 跟随最终 item 高度。

## 生命周期和性能约束

- 组件不主动创建分页流，不在组件内访问数据库；分页生命周期由页面通过 `flowWithLifecycle`、`collectAsLazyPagingItems` 等方式控制。
- `refresh Loading && itemCount == 0` 时展示独立 loading，不组合绑定同一个 `LazyListState` 的空 `LazyColumn`，避免空刷新窗口把滚动状态钳回顶部。
- Paging key 使用数据库主键，保证置顶、删除、搜索条件变化和侧滑状态保存时 Compose 复用稳定。
- 普通列表、普通搜索、折叠列表、折叠搜索和回收站的 DAO 分页查询必须在业务排序字段之后追加 `id DESC` 作为唯一兜底排序键；如果只按时间、置顶或命中质量排序，同毫秒记录可能在 Paging 分页边界重复出现，导致 `LazyColumn` 收到重复 `clip.id` key。
- 共享列表还要基于 `LazyPagingItems.itemSnapshotList` 做一次快照级 `clip.id` 去重，只保留当前已加载快照里首个出现的条目；原因是 Paging 在数据重排、失效切代或旧页回收边界上，仍可能短暂把同一条记录暴露两次，UI 需要先兜住重复 key 崩溃，再等待下一次稳定快照覆盖。
- 如果调整 item key、contentType、refresh 空态或侧滑状态保存方式，必须验证置顶、删除、搜索条件变化、切回页面、侧滑状态和滚动位置。

## 日志与诊断计划

- 本轮多选调整属于本地 UI 状态和手势分发，不访问网络、文件、数据库或系统权限，组件层不新增运行日志。
- 手势移动距离、选中 id 集合、剪贴内容、搜索词和来源 App 不写入日志，避免高频交互噪声和隐私泄露。
- 诊断方式以人工手势验证、编译验证和数据层测试为主：确认轻点仍进入详情，多选态轻点只切换选中，列表滑动和斜向短拖不会误进详情，普通态右滑菜单与第二段继续右滑仍按既有阈值触发，多选态右滑不再露出菜单或触发第二段动作。

## 已知取舍

- 共享组件只负责展示和回调，不直接决定普通列表、搜索或折叠列表的数据范围。
- 取消置顶后恢复的是操作时的 index/offset 视口，不保证继续显示同一条内容；这是为了满足“视口不动”的体验。
- 如果取消置顶同时发生新增、删除或后台刷新，恢复视口可能有轻微偏差，但会通过 index 边界保护避免崩溃。
- 右滑菜单采用单展开模式；当前展开 id 保存在 `ClipResultList`，如果已展开 item 因分页刷新离开可见快照，父层 id 可能暂时保留，但不会展示多个菜单，下一次展开会覆盖该 id。
- 第二段动作由页面传入，普通范围折叠，折叠范围取消折叠，回收站范围彻底删除；组件不理解具体业务，只负责触发时机、无菜单模式、选中态和离场动画。
- `ClipCard` 外层侧滑容器不做圆角裁剪，避免裁掉公共卡片阴影；右滑菜单和继续滑动提示层各自按同一 `cardShape` 裁剪，以保留圆角背景和阴影两种效果。
- 多选第一版只由普通列表和普通搜索接入；折叠列表、折叠搜索和回收站暂不通过本轮新增的批量折叠入口进入多选。

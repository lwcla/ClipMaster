### 筛选契约与状态边界

- 时间继续复用非空枚举 `SearchTimeFilter` 与 `labelText()`，默认选中 ALL，任意时刻恰好选中一项；普通搜索按剪贴时间过滤，折叠搜索按折叠时间过滤。点击已选项不取消，来源选择事件不能改写时间。
- 来源不再创建草稿或等待确认，勾选态即时应用。查询层沿用空集合表示“全部来源”的契约，集合内空字符串仍是“未知来源”的合法身份；全部勾选和全部未勾选都映射为查询空集合，部分勾选映射为明确包名集合。
- 为使“全部取消”在视觉上真实保留，筛选 UI 契约使用具名 `SourceAppSelection`：`All` 表示全部勾选，`Explicit(packageNames)` 表示显式勾选，允许集合为空。默认 All；`Explicit(emptySet())` 时所有复选框未选中，但查询不限制来源。这个状态是立即生效的选择状态，不是待确认草稿。
- `SearchFilterState` 中以 `sourceAppSelection` 作为唯一来源选择状态，查询用的 `sourceAppPackages` 改为由该状态派生的只读值，避免维护两份可修改集合。来源摘要使用有效查询范围决定；菜单复选框读取原始勾选态，不能从查询空集合反推为全选。
- “全选”使用普通复选框：All 时显示选中，部分或空选择时显示未选中。All 点击后变为 `Explicit(emptySet())`；部分/空选择点击后变为 All。All 中取消单项时先展开当前候选集合再移除；显式集合覆盖当前非空候选且没有缺失包名时归一为 All。所有来源操作保持时间、关键词和范围不变。
- 空选择边界（已确认）：取消全选或取消最后一个具体来源后保留无勾选态，来源入口显示“全部来源”，结果使用原时间条件和全部来源；菜单继续打开，不能自动恢复勾选、联动重置时间、禁用空选择或展示 0 来源无结果态。
- 候选为空时展示来源空态并禁用全选，不自动改写当前筛选。候选变化保留 All 或显式集合的语义，缺失候选仍通过现有摘要兜底展示；不能因重新打开菜单、候选刷新或查询空集合使无勾选态变回 All。单项变化只添加/删除目标包名，归一时不能丢弃缺失包名。
- 页面使用单一菜单状态 `None/Time/Source` 表达展开项，防止两个菜单同时打开；菜单展开态是临时 UI 状态，不存入 ViewModel、DataStore、Room 或备份。来源已应用状态继续由 ViewModel 持有。
- 菜单入口与浮层位于同一锚点布局中，随搜索头真实位置定位；菜单展开期间暂停结果驱动的搜索头折叠/吸附，避免锚点移动。关闭后恢复原有滚动规则，不强制改变展开/收起状态或列表位置。
- 打开和关闭菜单不修改查询、不清空结果多选，也不切换 History/Result。有效时间或来源查询条件实际变化时立即退出结果多选并查询；All 与无勾选态切换只更新菜单视觉，有效查询条件相同，不重建分页、不清空结果多选。结果查询按关键词、时间和派生的来源包名集合判断变化，不能把原始勾选态变化当作查询变化；广告访问保持稳定作用域，不随查询条件更换。
- 菜单获得焦点导致搜索框短暂失焦或关闭后恢复焦点时，不自动切换页面模式、不保存历史、不重新请求输入法；`SearchInputFocusGuard` 屏蔽被动恢复。主动触摸、键盘导航、语义点击或编辑解除保护，搜索框聚焦后按现有规则进入历史；语义点击可显式聚焦并打开输入法。
- 返回顺序：菜单打开时优先关闭，保留已即时生效的来源选择；菜单关闭后沿用结果多选、输入法与导航现有返回链路。外部点击仅关闭菜单，不把同一次点击穿透为结果操作。
- 页面不再可见、进入后台、离开搜索范围或窗口重建时关闭浮层，不回滚已应用条件；来源候选 Flow 继续生命周期感知收集，不为菜单新增扫描或持续后台任务。
- 新菜单展开态继续接入现有 `adOverlayBlocked` 与广告交互保护；有效来源变化只更新业务查询，所有查询与原始勾选态变化均不重建广告访问或启动广告稳定计时；菜单打开期间继续阻止广告交互与布局变化，关闭后沿用同一会话。

- 搜索页顶部不显示页面标题，输入行内提供返回箭头；关闭菜单、退出结果多选后，显式返回收键盘并离页。系统返回继续沿用现有输入法和导航处理链。

- 历史模式不再注册专用返回处理；第一次系统返回交给输入法收起，输入法已关闭时下一次返回直接退出搜索页。
- 历史模式下修改筛选继续停留在历史模式；菜单导致短暂失焦/恢复焦点均不切模式。只有真实点击输入框或编辑才按原有交互进入历史模式。
- 提交搜索或点击历史项后切到结果模式并收起输入法；空关键词搜索展示当前时间/来源筛选下的全部结果，但不写入搜索历史。
- 结果模式下再次点击输入框会回到历史模式；清空搜索词保持输入框焦点并展示最近历史。
- 从搜索页进入详情页再返回时，当前回栈实例保留搜索头展开/收起状态和结果列表位置；退出搜索页后重新进入新的搜索页实例时，搜索头默认完全展开。
- 普通搜索和折叠搜索虽然复用同一页面实现，但保存态必须按搜索范围隔离，避免搜索头状态、Result/History 模式、结果列表位置或历史列表位置互相串写。
- 当搜索关键词非空时，在搜索结果卡片的可见文本中高亮命中的关键词。
- 当没有结果时展示搜索页专用空状态文案。

## 高亮规则

- 高亮只针对关键词搜索，不针对时间筛选或来源 App 筛选。
- 第一版高亮范围包含：
  - 剪贴内容 `content`
  - 链接预览标题 `linkTitle`
  - 来源 App 名称 `appName`
- 不高亮不可见字段，例如链接描述、站点名、包名等；这些字段可以参与搜索命中，但不应让用户看到没有上下文的高亮。
- 高亮实现建议通过 `AnnotatedString` 完成，普通列表页传空关键词，搜索页传当前搜索词。
- 搜索词需要先去除首尾空白，按空格拆分多个词，并去重，避免空关键词导致异常高亮。
- 英文、URL 和包名类内容按大小写不敏感匹配。
- 第一版优先高亮完整词；中文 FTS 模糊命中但可见文本里没有完整词时，暂不做逐字碎片高亮，避免视觉噪声。

## 数据方案

- 现有 `ClipRepository.searchAllClips(userInput)` 只支持关键词，并返回 `Flow<List<ClipShowEntity>>`；搜索页第一版建议改为分页数据流，避免历史数据较多时一次性加载。
- 在 `ClipDao` 增加搜索用 `PagingSource<Int, ClipDetail>` 查询，支持以下参数：
  - 关键词查询
  - 起始时间 `startTime`
  - 结束时间 `endTime`
  - 来源 App 包名集合 `sourceAppPackages`
- 关键词为空时，按时间和来源 App 集合条件查询全部匹配记录。
- 关键词非空时，复用现有 FTS 查询思路，并叠加时间和来源 App 集合条件。
- 来源 App 筛选状态使用空集合表达“全部来源”，非空集合表达多选包名；DAO 查询使用 `IN (:sourceAppPackages)` 匹配任一已选来源。空字符串包名是“未知来源”的合法筛选键，ViewModel 和 Repository 只做去重、排序与必要的首尾空白规整，不能把它过滤成空集合。
- 搜索结果排序沿用当前范围的时间语义：普通搜索置顶优先并按剪贴时间倒序；折叠搜索同样置顶优先，关键词命中质量之后按折叠时间倒序；所有搜索 Paging 查询都在最后追加 `id DESC`，用于同分同时间数据的唯一稳定排序，避免分页边界重复返回同一剪贴记录。
- 在 `SourceAppDao` 增加加载全部来源 App 的查询，供搜索页筛选器使用。
- Repository 层暴露搜索分页数据和来源 App 列表给 `SearchViewModel`。

## 已知取舍

- 磁力搜索不并入本文档的剪贴搜索页；两者只复用底层通用输入框、分页状态和卡片外壳等 UI 组件。原因是磁力搜索的数据源、合法源白名单、索引缓存、磁力记录和外部 App 打开副作用都不同于剪贴内容搜索。
- 第一版时间筛选先使用固定范围，不做自定义日期区间，以降低 UI 和本地化复杂度。
- 第一版中文高亮优先高亮完整词，不做逐字碎片高亮，避免结果卡片视觉过碎。
- 普通搜索结果排序沿用列表页置顶优先规则，方便用户在普通搜索页继续看到被置顶的重要内容。
- 第一版多选只接入普通搜索结果，不接入折叠搜索；原因是本轮批量折叠只针对正常未折叠记录，折叠搜索的批量动作需要另行确认取消折叠或彻底删除等语义。
- 折叠搜索保留置顶优先规则；和普通搜索不同的是，置顶组和非置顶组内部的时间排序使用折叠时间而不是剪贴时间。
- 对只包含标点或 FTS 特殊字符的关键词，最终实现会退回普通 LIKE 查询；这是为了让 URL 片段、符号输入等场景不因 FTS 语法失败而中断搜索。
- 对可构造 FTS 的关键词，最终实现也会并入 `LIKE` 子串结果；代价是关键词搜索会比纯 FTS 多一次主表扫描，但能保证中文连续子串的命中率。
- 普通搜索不增加“包含折叠数据”开关，折叠数据只能从折叠数据入口进入搜索，保持可见范围边界清晰。

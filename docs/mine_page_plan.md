# 我的页方案

## 当前状态

我的页是首页底部 Tab 的一级页面，依次展示权限项、备份与恢复、下载记录、折叠数据、回收站和检查更新入口；启用 TorrentSearch 时，页面通过可发现的 `TorrentSearchFeatureEntry` 追加轻量入口，以空查询和 `mine` 稳定启动来源打开独立 Activity。TorrentSearch、下载记录、折叠数据和回收站只在入口处展示轻量说明或统计，不在我的页预热 Provider、同步索引、执行搜索或加载对应分页数据。检查更新入口只负责触发轻量版本检查、展示结果和打开外部发布链接，完整自更新规则以 `docs/app_update_plan.md` 为准。本轮 UI 刷新后，我的页通过 `TopLevelPageScaffold` 接入统一一级页骨架，并按“权限”“数据管理”“功能入口”“设置”分组展示入口。

本文记录我的页自身的入口、设置项和页面级交互；首页 Pager、底部 Tab 和一级标题详见 `docs/main_page_plan.md`，共享剪贴 item 的斜向快捷动作区、右滑菜单和回调规则详见 `docs/clip_result_list_plan.md`。

当前代码组织已将我的页入口卡片、剪贴快捷动作设置弹窗和权限设置项适配层拆到同 package 组件文件中；`MinePage.kt` 保留页面状态收集、权限动作消费、生命周期刷新和系统跳转，避免页面入口继续混合所有 UI 细节。入口卡片、入口式开关卡片、单选弹窗、固定设置开关列表和设置开关行的完整共享规则以 `docs/shared_form_components_plan.md` 为准，本文只记录我的页接入方式和快捷动作业务差异。

“剪贴保存过滤”是我的页设置分组中的全局规则入口，完整规则、本地安装扫描及随扫描读取图标、备份恢复和保存链路边界以 [来源过滤主方案](clip_source_app_filter_plan.md) 为准；本文只记录我的页入口与导航接入。2026-09-30 用户批准执行即时生效、下拉刷新、顶部系统开关及移除清空/手动添加，当前过滤页已完成，保留已过滤优先，完整验证及设备验收边界以主方案为准。

## 目标

- 保持我的页作为管理入口和偏好设置入口，避免在首页列表里堆叠全局设置。
- 新增“剪贴快捷操作”设置，让用户理解普通列表和普通搜索结果 item 可以通过斜向快捷动作区执行所选动作。
- 设置快捷动作时提供复制、置顶、删除、折叠、无（整卡进入详情）五个互斥选项，并在选择后立即影响普通列表和普通搜索结果。
- 新增“剪贴保存过滤”入口，让用户集中管理哪些来源 App 的后续剪贴不保存，同时明确历史记录不受影响。

## 用户体验

- 我的页继续使用单列卡片入口，顶部显示固定标题“我的”，入口按权限、数据管理、功能入口、设置分组。
- 权限分组固定放在我的页最上面，只展示 Shizuku 和通知两个权限项；两个权限项各自独立成卡，方便用户先看到影响剪贴读取和提醒展示的系统能力状态。
- 备份与恢复、下载记录、折叠数据、回收站以及可选 TorrentSearch 入口只保留卡片自身点击反馈；TorrentSearch 启动独立 Activity，其内部转场不由宿主导航负责。
- TorrentSearch 入口只在实现启用时出现，并且只负责以空查询启动 Activity；Provider、搜索历史和结果分页均在功能内部按生命周期启动。
- 检查更新入口展示当前 App 版本，点击后执行手动版本检查；Gitee 与 GitHub 更新源均不可达时展示“暂时无法检查更新，可稍后重试或前往发布页查看”，并提供可配置发布页入口。
- “剪贴快捷操作”作为普通设置行展示当前选项摘要，例如“当前：复制”。
- 点击该设置行打开单选弹窗，选项顺序为复制、置顶、删除、折叠、无（整卡进入详情）。
- 弹窗说明普通列表和普通搜索结果 item 的快捷动作区执行所选动作，其余区域进入详情；选择“无（整卡进入详情）”会关闭快捷动作区。
- 该设置是五选一偏好，不使用开关，避免把互斥动作误表达为启用/停用。
- “剪贴快捷操作”设置行只打开本页弹窗，不参与页面级导航转场。
- “权限”分组不再提供“权限说明”标题行、收起/展开按钮或展开动画。
- Shizuku 和通知权限不放在同一个卡片里，每个权限项都单独使用一张卡片，和其他分组入口保持一致的扫描节奏。
- 权限单项卡片内部展示权限语义图标、短标题、完整说明文案和右侧开关；短标题用于和其他入口卡片保持一致的扫描节奏，说明文案继续承载权限影响边界。
- Shizuku 和通知权限项的说明文案必须完整换行显示，不使用两行省略，避免用户看不到通知关闭后“剪贴仍会保存”等关键说明。
- 通知权限项只表达剪贴保存、下载进度、下载结果和 Shizuku 状态提醒的展示能力；关闭通知不影响剪贴入库。
- “剪贴保存过滤”作为设置行展示未设置或已过滤数量，点击后进入独立二级选择页。
- 当前过滤页仅展示本机扫描结果，默认严格排除系统应用，开关变化重新扫描名称及图标，已保存和搜索不提供系统应用例外；隐藏规则继续保留在完整名单中。本轮改为单项原子即时提交，完整行为及失败边界以来源过滤主方案最新章节为准。
- 本轮调整：过滤页逐项立即提交并支持下拉刷新，系统开关位于顶部右侧，移除页面确认、清空和手动添加；我的页入口与导航不变，入口数量随已提交名单更新。完整交互、错误、生命周期与验证只维护在来源过滤主方案，不在本文重复设计。

## 数据和接口

- 快捷动作经 `ClipSettingsRepository` 写入宿主 DataStore，默认值为复制；首次加载或读取失败前禁用设置编辑，失败可重试。
- 我的页 ViewModel 只负责读取和写入设置，不直接操作剪贴列表数据。
- 普通列表页和普通搜索页观察同一设置状态并传给 `ClipResultList`；折叠列表、折叠搜索和回收站忽略该设置。
- 后续新增剪贴 item 快捷动作时，需要同步扩展设置枚举、字符串资源、单选弹窗选项、共享 item 动作映射和本文档。
- 来源过滤名单读取 `ClipSettingsRepository.blockedPackages`，快捷动作独立读取 `ClipSettingsRepository.quickAction`；页面只合并两路读取失败标记用于统一重试入口，候选仅来自当前 `PackageManager` 扫描的安装应用，系统应用是否参与由页面开关决定；完整已保存名单仍独立保留；读取失败时提供重试且不允许以空名单覆盖已保存规则。安装应用读取结果、读取状态和当前安装图标不持久化、不进入 WebDAV/本地备份，搜索页来源筛选仍只读取 `source_apps`。
- 来源过滤名单保存后标记 backup dirty 并调度自动备份；具体备份字段和恢复并集策略见 `docs/clip_source_app_filter_plan.md` 与 `docs/webdav_backup_plan.md`。
- 检查更新使用 app 模块内的自更新协作者；我的页只持有入口 UI state、触发检查和分发外部链接打开事件，不承载 manifest 解析、版本比较或下载源排序逻辑。
- Shizuku 和通知权限项只使用页面内瞬时状态，不保存“权限说明是否展开”的 MMKV 偏好；历史 `permission_expanded` key 已废弃且不进入备份恢复协议。

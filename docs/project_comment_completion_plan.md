# 项目注释补全方案

## 当前状态

项目已有较多简体中文注释，但覆盖不均衡：部分新增的图片提取代码已经补齐较完整注释，其他模块仍存在类、字段、私有辅助方法、Composable、Worker、Repository、DAO 或工具函数缺少说明的情况。当前 `AGENTS.md` 已明确要求新增或修改代码时同步补充注释，并进一步补充了私有方法、实体字段、Compose 辅助函数、每个方法和每个变量声明的注释规则。

本轮已完成生产代码核心路径的声明级和关键逻辑注释补齐，覆盖应用入口、导航、主页面、列表、搜索、详情、我的页、图片提取、视频提取/下载、剪贴板服务、Shizuku 服务、下载 Worker、DAO、Repository、实体、配置和通用工具。未主动扩展到测试样例、隐藏 API 壳代码和无业务含义的模板文件。

## 目标

- 对生产代码中的核心类型、字段、方法、Composable、Worker、Repository、DAO 和工具函数补充简体中文注释。
- 后续新增或修改代码时，每个方法声明和每个变量声明都必须补充贴近代码的简体中文注释；同一语义组的多个局部变量可以共享紧邻注释，但注释必须逐一说明每个变量含义。
- 注释重点说明职责、调用时机、输入输出、生命周期、线程/协程边界、数据约束、用户体验取舍和平台兼容风险。
- 优先补齐 `src/main` 下业务代码，不调整测试样例、生成壳代码或无业务含义的空模板。
- 不改变现有业务行为、UI 文案、数据结构和接口契约。

## 范围

- `app/src/main/java/com/cla/clip/master/**`
- `base/general/src/main/java/com/cla/clip/base/general/**`
- `shizuku/src/main/java/com/cla/clip/shizuku/**`
- 不主动修改 `src/test`、`src/androidTest`、`base/hidden-api` 中为兼容隐藏 API 保留的 Java 壳文件，除非后续业务代码依赖其注释说明。

## 用户体验

本次任务主要提升源码可读性、维护性和后续协作效率。过程中发现并修正了少量已触碰文件中的用户可见硬编码文案，将底部 Tab 无障碍描述、视频手动播放提示、下载/合并进度文案迁移到字符串资源，展示语义保持不变。

## 实现步骤

1. 扫描生产代码中的 Kotlin/Java 文件，按模块统计待补注释区域。
2. 先补齐入口、导航、页面、ViewModel、Worker、Repository、DAO、实体和工具类等高价值文件。
3. 对 Compose 私有 UI 片段、remember 辅助函数、格式化函数和状态分支补充职责说明。
4. 对实体字段、Room 字段、路由字段、任务 key、状态常量和缓存字段补充取值限制、读写方和修改风险说明。
5. 保持代码行为不变，完成后运行 `./gradlew :app:compileDebugKotlin` 验证。
6. 按实际补注释范围更新本文档状态和变更记录。

## 测试验证

- 已运行 `./gradlew :app:compileDebugKotlin`，编译通过。
- 人工抽查关键文件，确认新增注释解释的是业务原因和边界，而不是重复语法。

## 已知取舍

- 本次只补生产代码注释，不重构实现，也不借机修复既有命名或架构问题。
- 对已触碰文件中发现的用户可见硬编码文案做了资源化处理，避免违反字符串资源规范；未扩大到全项目字符串专项治理。
- 对非常直观且无业务含义的样板测试文件暂不补注释，避免制造低价值噪声；但后续一旦新增或修改业务代码中的方法和变量声明，默认仍要按最新规则补齐简体中文注释。
- 对第三方或平台壳代码保持克制，避免误导维护者以为这些 API 由本项目实现。

## 开放问题

- 后续可以增加静态检查或代码评审清单，防止新增代码再次漏掉私有 Composable、实体字段或辅助函数注释。

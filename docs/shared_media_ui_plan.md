### Telephoto 接入与缩放契约

- **组件选择**：采用 Telephoto 的 `ZoomableAsyncImage`，依赖为 `me.saket.telephoto:zoomable-image-coil3`。官方提供 Coil 3 集成、完整 `ImageRequest` 与自定义 `ImageLoader` 入口、缩放/平移和大图分块能力，见 [Zoomable Image 文档](https://saket.github.io/telephoto/zoomableimage/) 与 [分块加载文档](https://saket.github.io/telephoto/zoomableimage/sub-sampling/)。继续复用项目图片请求头及动图加载器，缩略图保持现有组件。
- **依赖归属**：`gradle/libs.versions.toml` 固定 Telephoto 0.19.0，`app/build.gradle.kts` 引入 Coil 3 集成。结合项目 Coil 3.4.0、Compose BOM 2026.03.01 已完成 Debug、设备用例及 Release/R8 构建验证，不使用动态版本。
- **缩放与平移**：普通图初始完整适配视口，支持双指缩放、双击在适配大小与放大状态间切换、放大后拖动查看细节；默认缩放边界沿用库的合理约束。长图采用适合阅读的按宽度、顶部对齐展示，平移由 Telephoto 处理，避免再在同一区域叠加 `verticalScroll` 或自写 `detectTransformGestures` 竞争指针事件。
- **与翻页协作**：未放大且图片没有可消费的横向位移时，单指横滑切换图片；放大后优先平移，达到横向边界后继续向外拖动交给 Pager。双指操作期间保持当前图片，不触发翻页。优先使用 Telephoto 的嵌套滚动能力，这一段是项目期望的验收契约，仍需验证当前依赖组合，不能当作已测通过的库保证。
- **状态边界**：以预览内容会话和图片稳定 key 关联每张图的缩放/平移状态；同次预览往返切图保留各自位置，新图从初始状态打开。追加其他图片、计数或勾选变化不重置当前缩放；尺寸变化只校正合法边界。关闭预览、重新提取或切换批次释放会话状态，沿用当前配置变化关闭预览的约定。状态处理参考 [Telephoto 状态文档](https://saket.github.io/telephoto/zoomable/recipes/)，不把位图或请求对象保存进状态容器。
- **点击与布局**：有界图片区承载可缩放内容，顶部关闭和底部计数/操作放在其外，不随图片缩放。需要图片点击回调时使用组件提供的 `onClick` 等入口，避免外加 `clickable` 抢占双击；本期不添加点击图片关闭或隐藏工具栏的交互。
- **边界与失败**：大图优先使用库已有的分块能力，不另写分块引擎；不把分块能力等同于所有格式都不会内存不足。GIF/Animated WebP 的加载、播放、缩放及离屏停止需沿用现有加载器并实测。兼容性或解码失败不能静默退化为取消缩放，需修复并重新验收。

### 用户体验与范围

- 点击任意缩略图，直接全屏显示该图；左右滑动按当前网格图片顺序切换，首尾停止，不循环。单张图片显示 `1 / 1`。
- 顶部保留明确关闭按钮，系统返回先关闭预览；关闭后保留原网格滚动位置、勾选状态及提取进度。重新点击图片，以本次点击目标打开。
- 预览采用深色背景覆盖应用内容，普通图片初始按比例完整展示；支持双指缩放、双击放大及拖动，长图可纵向查看完整内容。缩放、平移与 Pager 的衔接遵循上节契约，每张图独立保留本次预览内的缩放和位置。
- 底部固定显示从 1 开始的 `当前位置 / 当前图片总数`，页码以滑动落定后的图片为准；总数来自最新的完整图片集合，不是已选数、成功下载数或 Pager 已加载页数。新增图片时例如 `3 / 8` 更新为 `3 / 12`，不会自动跳到新增图片。
- 候选阶段保留分辨率、类型、体积及“保留/移除这张图片”操作，信息区采用紧凑布局，计数固定可见；操作仅改变下载选择，不删除候选、不减少总数。默认浏览全部候选，包含未勾选图片。批次阶段浏览当前批次网格全部图片，无候选勾选操作；失败/过滤项仍可查看其可用图片源。
- 底部可附“仍在提取”状态，完成后撤去提示，预览继续停留在当前图片。顶部、底部控件处理系统栏安全距离和横屏窄高布局；计数及按钮均有字符串资源和无障碍语义。
- 单图加载中显示占位，加载失败提供当前图重试；失败不会移除条目，仍可左右切换或关闭。GIF/Animated WebP 等沿用现有解码能力。

以上交互已落实；候选预览实时同步，批次预览使用打开时的图片集合。

### 数据来源、身份与状态协调

数据流：页面最新候选或打开时的批次快照 → 同帧绑定的稳定 key 与图片数据 → 共享全屏 Pager → 落定项 footer → 页面读取元信息与选择状态。共享组件只保留渲染快照和局部定位状态，不读取 Repository，不创建新的数据库观察或轮询。

1. **稳定身份**：候选沿用 `viewModel.candidateKey(candidate)`，与 URL 变体升级和选择状态保持一致；批次沿用现有 `asCandidate()` 的候选键，不能直接改成下标、当前 URL 或尚未落库的 item id。外层内容会话使用候选 `extractionId` 或批次 `batchId` 区分；普通后台恢复引起的探测 `sessionId` 变化不等同于用户重新提取。
2. **原子列表快照**：复用 `snapshotMediaGridItems` 将 key 与内容一次性绑定，每次列表内容改变重新生成不可变快照。`pageCount`、Pager key、取页内容和总数必须使用同一版本，不能分别读取可变列表。该函数虽然按网格命名，现有契约只是纯媒体快照，不含广告/布局；复用时补充适用 Pager 的注释，无需复制实现或顺带重命名所有调用方。不能仅使用 `remember(candidates)`，因为当前列表会在同一实例内追加/替换。
3. **初始定位**：打开事件保存点击 key，首次按最新快照找到其位置；点击与渲染之间目标已消失时安全关闭预览，不误开另一张。图片 key 作为 Pager 的稳定 key，页码只是显示及临时滚动位置。
4. **追加与内容更新**：候选会话追加图片立即更新页数和总数；同 key 的 URL、尺寸或选择变化只刷新对应项，不重建整个 Pager、不回到首次点击的位置；缩放和平移按图片 key 保留，尺寸变化时只校正合法边界。批次入口仅消费打开时的集合快照。
5. **重排与移除兜底**：当前 key 仍存在则保持该图片，按最新顺序更新位置数；真正移除当前图片时，选择旧下标在新列表对应的图片，若旧下标超出末尾则选最后一张。最终快照为空时关闭预览，不出现 `0 / 0` 或越界。候选发布内部 `clear/addAll` 的中间状态不能被当成有效空集合发给 Pager；实施时验证发布原子性，必要时将这两步纳入同一 Compose 快照事务，不靠延迟关闭来掩盖真正清空。
6. **手势竞争**：区分初始打开、用户翻页和数据校正。用户翻页落定回传当前 key；追加不能触发 `scrollToPage` 打断拖动。只有结构性变化确实改变当前 key 的位置时才校正；拖动中发生重排/删除应合并到落定时按最新 key 重新核对，任何延迟回调都要校验内容会话和快照版本，避免旧下标覆盖新选择。
7. **会话结束**：自动提取完成沿用同一预览会话；显式重新提取、批次更换、离开页面时关闭并清理。普通前后台切换保留当前内存 key，回来后先与最新列表核对。配置变化沿用当前临时预览关闭策略，不把全列表、URL、Cookie 存入 SavedState；可在后续需求中单独评估旋转保留。

### 生命周期、请求与性能

- 全屏采用当前页面上的 Dialog，不新增导航目的地；打开预览时保留原探测 WebView 实例和页面组合，让前台提取继续发布图片。预览显示不修改探测会话，不触发重新加载、重复下载或新的 Worker。
- 图片加载及元信息任务依赖预览存在且宿主生命周期为 STARTED；关闭、离开前台、切图或请求身份变化后取消对应辅助任务。页面隐藏时移除图片请求子组合/停止动图，不仅取消 HEAD 协程；批次观察继续使用 `collectAsStateWithLifecycle`，Worker 保持独立运行。
- 只对落定的当前图片读取 HEAD/Range 元信息，复用 `ImagePreviewMetadataReader` 的三秒预算和底层 Call 取消。相邻页可以用于翻页显示，但不为全列表创建请求、探测体积或播放全部动图；首期不主动扩大 Pager 默认预取范围。
- 元信息的图片 key 与请求版本分离：同 key 的 URL/有效请求上下文变化时废弃旧请求版本的 MIME/体积及解码尺寸，先用新候选已知值兜底，再按需读取。写回前检查内容会话、图片 key 与请求版本；旧任务结束时也不能清除新任务的 loading 状态。稳定 key 只保证图片身份，不保证同一 URL 变体的文件属性一致。
- Coil 请求保留 Accept、Referer、User-Agent、Cookie，复用同一个加载器。
- Telephoto 按实际可见页及宿主前台状态启动、取消请求和分块任务；拖动中仍露出的旧页不会提前停止显示。全屏首次解码覆盖为视口像素尺寸，不提前分配整张大位图；原图尺寸只从未采样结果或缓存头获取。大静态图、长图、多动图快速翻页时的内存峰值仍需专项设备测量。
- 预览打开期间延续网格广告 `blocked` 规则；广告不是图片，不进入快照、位置和总数。关闭后按原资格恢复；不在本方案扩展广告生命周期。

## 组件归属规则

- Compose 组件默认按公共组件设计。只要组件表达的是视觉结构、交互模式、布局容器、预览弹层、选择控件、状态展示或常见操作区，而不是当前页面独有状态机，就应优先放在 `ui/widget` 或合适的共享 UI 包中。
- 公共化按复用半径分层：同一 feature 多页面复用时先放 feature 级组件目录；跨 feature 或后续多个业务域可能复用时放到 `ui/widget` 或共享 UI 模块，避免所有组件无差别集中到一个目录。
- 页面目录只保留强绑定当前页面 ViewModel、导航、权限、一次性副作用、路由参数或特定业务实体且难以解耦的组件；这类组件需要能说明为什么只能用于当前页面。
- 页面可以保留薄适配层，将 `ImageExtractItemData`、`ImageCandidateData` item 等业务实体转换成共享组件需要的 UI state、请求模型和事件回调；共享组件本身不直接依赖页面 ViewModel、Repository 或具体数据库实体。
- 当前只有一个页面使用但形态明显通用的组件，也应优先公共化，避免后续页面复制实现；如果因风险或需求不稳定暂不公共化，需要在对应页面文档的“开放问题”或“后续待办”中记录原因和收敛方向。
- 公共组件参数优先使用具名 UI state、config、sealed state、slot 和 callback。出现大量 `isXxx`、`showXxx`、`enableXxx` 或可空参数组合时，需要重新评估状态建模，避免组件演变成万能入口。
- 公共组件默认提供 `modifier: Modifier = Modifier`；复杂内容区域优先提供 slot，例如标题、操作区、页脚和空态内容，避免为了单个页面追加一次性参数。
- 文案由语义稳定性决定位置：跨页面通用文案可以由共享组件读取字符串资源；页面语义、业务动作、错误原因、统计口径和流程提示应由调用方传入。
- 共享组件内部只保留展开、滚动、动画、焦点、临时输入等纯 UI 局部状态；导航、权限、下载启动、数据库观察、网络请求和跨页面业务副作用必须留在页面、ViewModel 或专门 state holder。
- 复杂公共组件应提供 `@Preview` 或 sample state，并覆盖正常态、空态/失败态、长文案或极端内容中的关键场景，便于后续独立验证，不依赖完整页面启动。

## 最终实现

- 2026-10-16：`ProbeWebView` 是两页唯一 loadUrl 与释放入口，按目标/session 建立实例；内部重定向不重载入口，每次主文档导航的完成回调去重，新文档通知页面取消旧扫描。`onRelease` 先关回调，再 stop/destroy；`ProbeLifecycleEffect` 把 START/STOP/退出组合连接到业务会话，正式 Worker 不受其影响。
- `MediaAdGrid` 接受外部 `LazyGridState`，默认仍自行记忆；图片页在候选和批次间复用状态，不改变其他调用方。`MediaTaskTile` 和预览弹层接受同一个动图 ImageLoader 及已有缓存配置。

- `ui/widget/image` 承载全屏预览容器、Telephoto 单图、元信息、尺寸读取和定位规则；`SharedImagePreview.kt` 保留缩略图、动图加载器、请求构建、格式化和不可读占位。
- 共享图片请求通过 `ImageRequestHeaderBuilder.IMAGE_REQUEST_ACCEPT` 复用 Worker 下载链路的图片 Accept，避免预览和下载内容协商规则分叉。
- `ImagePreviewComponents.kt` 保留图片提取页的实体适配层，只把 `ImageCandidateData` 转成共享图片请求与共享预览元信息。
- `ui/widget/MediaStateContent.kt` 负责居中状态容器和行内加载/成功/失败状态。图片提取页与视频提取页接入该组件，页面只决定文案、点击回调和后续业务动作。
